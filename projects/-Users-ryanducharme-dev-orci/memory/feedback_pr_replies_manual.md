Never post replies to GitHub PR comments, reviews, or threads unless Ryan explicitly says to. Ryan handles all PR communication himself.

**Why:** Ryan manages PR conversations directly. Unsolicited replies — even to acknowledge feedback that has been resolved — are not wanted.

**How to apply:** When addressing PR feedback, make the code changes and stop. Do not post a reply comment. If Ryan asks for a reply to be drafted, write it in Ryan's voice (first person as Ryan) — super simple, high level, conversational: short sentences, plain words, only the points that matter. He still paraphrases before posting, but drafts that sound like him are easier to work with and help him understand the reasoning. (Changed 2026-07-27; previously drafts were in Claude's voice.)
